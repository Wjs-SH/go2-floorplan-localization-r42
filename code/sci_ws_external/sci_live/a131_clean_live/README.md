# a131_clean_live — 정제(이중반사·사람·움직이는 물체) 실시간판 (2026-10-08)

10-08 요청서에 대한 답입니다. 녹화본 정제(`build_a131_clean_bag_v7.py`)가 하던 일을 **지금까지 들어온 스캔만으로** 합니다.
`a131_live` 와 같이 ROS 없는 Python 이고, 요청하신 (a) 스캔 정제 자리에 들어갑니다.

## 쓰는 법

```python
from a131_clean_live import LiveCleaner

C = LiveCleaner(static_matrix=T_base_lidar, support_stride=2)

# 건너뛰는 스캔(쓰지 않는 12개)도 이력에만 넣어 주세요. 움직이는 물체 판정에 1·2·3초 전 스캔이 필요합니다.
C.observe(scan_id, x, y, z, ring, t_sec, interp)            # 또는 pose=(x, y, yaw)

# 쓸 스캔
x, y, z, i, ring, t = C.clean(scan_id, x, y, z, intensity, ring, t_sec, interp)   # 지운 점 = NaN
L.add_scans(...)                                             # 그다음 a131_live 에 넣으시면 됩니다
```

`interp` 는 `a131_live` 가 쓰는 PoseInterpolator(`matrix_at(ns)` → 4x4)를 그대로 넘기면 되고,
자세를 직접 갖고 계시면 `pose=(x, y, yaw)` 로 주셔도 됩니다. 점 개수·순서·ring·timestamp 는 건드리지 않습니다.

far 점은 정제된 스캔에서 뽑으시면 같이 정제됩니다. `clean()` 을 거친 배열을 target 스캔으로 쓰시면 됩니다.

## 질문 세 가지에 대한 답

**1) 오프라인 정제는 몇 단계이고 무엇을 입력으로 쓰나**

| 단계 | 입력 | 인과 | 이 PC 1코어 ms/스캔 |
|---|---|---|---|
| 이중반사(near-echo) | 스캔 하나 | 예 | 1.9 |
| 면 위 리턴 살리기 | 스캔 하나 | 예 | 18.7 (stride 2 로 9) |
| 따라오는 사람 | 과거 12초 경로(자세만) | 예 | 8.1 |
| 움직이는 물체 | 과거 1·2·3초 스캔 + 2~5초 점유 | 예 | 23.5 |
| (제외) 스캔-국소지도 ICP | 과거 25스캔 | 예 | 185.3 |
| (제외) 거울상 규칙 v6 | — | — | 전달본은 전부 꺼 둠(mirror_pts=0) |

**녹화 전체가 필요한 단계는 정제 bag 안에 없습니다.** 네 단계 전부 과거만 봅니다.

ICP 는 뺐습니다. 점을 미는 양이 층마다 중앙 0.35~0.62 cm 였고(1F 0.61 · 2F 0.62 · 3F 0.40 · 4F 0.53 · 5F 0.56 · G1 0.36 · G2 0.35),
끄고 켜고 재 보니 이웃 스캔 어긋남이 2.0 cm → 1.9 cm 로만 바뀝니다. 185 ms 를 쓸 값이 아닙니다.

**2) 유령점 목록을 과거만으로 키워도 되나**

유령점 마스크는 두 가지가 섞여 있습니다.
- 경로 위 잔상: 과거 경로만 쓰므로 실시간으로 그대로 됩니다. 이번 판의 "따라오는 사람" 단계가 같은 일을 합니다.
- 이중반사 평행선(3층 아래 복도, 4층 오른쪽 위 복도): 녹화 전체 통계로 선을 찾고 **사람이 그림을 보고 고른** 것입니다. 자동이 아니었습니다.

과거만으로도 원리는 같지만 그 벽 옆을 지난 뒤에야 판정이 서고, 60초 창에서는 통계가 얇아 진짜 벽을 지울 위험이 있습니다
(3층에서 구간별 자동 검출을 시험했다가 벽이 날아가 버린 적이 있습니다). 그래서 1차에서는 넣지 않았습니다.
스캔 단계 이중반사 제거만으로 유리벽 가짜 벽이 상당 부분 사라지니, 60초 누적을 보시고 남으면 그때 붙이겠습니다.

**3) 스캔 단계인가 결과 단계인가**

스캔 단계가 원래 파이프라인과 같습니다. 전달본은 bag 스캔에서 지운 점을 NaN 으로 바꾼 것이고 far 도 그 스캔에서 뽑습니다.

## 검증 (3층 485~545초, 사람이 가장 많은 구간)

원본 bag 을 LiveCleaner 로 정제해서, 같은 구간 오프라인 정제본과 점 단위로 대조했습니다.

| | 값 |
|---|---|
| 오프라인이 지운 점을 실시간이 지운 비율 | **100.00%** |
| 실시간이 더 지운 점 | 0.5~1.8% (stride 1 / 2) |
| 스캔당 시간 | 54 ms (stride 1) · 45 ms (stride 2), 이 PC 1코어 |

`support_stride` 는 "면 위 리턴 살리기"에서 기준으로 쓸 점을 몇 개에 하나 볼지입니다. 2 로 두면 9 ms 아끼고,
살려 둘 점을 조금 덜 살려서(=조금 더 지워서) 더 지운 점이 0.5% → 1.8% 로 늘어납니다. Orin 에서 시간이 빠듯하면 2~3 으로 쓰세요.

Orin NX 환산은 이 PC 의 2.5~3배로 보시면 됩니다(135~160 ms, stride 2 기준). 1.5초에 스캔 3개면 0.4~0.5초입니다.
`observe()` 는 방위 720칸 최소거리만 쌓으므로 스캔당 수 ms 입니다.

## 로봇 FAST-LIO 축 (5절 질문)

우리 규약은 `base_x` = 로봇 전진, `base_y` = 왼쪽입니다. δ 는 **직진 구간의 이동 방향이 base_x 와 같아지도록** 맞추는 값이라,
보내 주신 −90.8° 는 그 방법으로 구한 값이니 맞습니다. 거울상(켬/끔)은 좌우 회전 부호로 확인하시면 됩니다.
제자리에서 왼쪽으로 한 바퀴 돌렸을 때 yaw 가 **증가**하면 맞고, 감소하면 거울상을 반대로 두시면 됩니다.
